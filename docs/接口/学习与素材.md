# 题库、简历导出、检索、资源与上传

对应后端 `app/routes/quiz_routes.py`、`resume_routes.py`、`search_routes.py`、
`resource_routes.py`、`upload_routes.py`。
通用约定见 [接口文档总览](./README.md)。下文路径省略 `/api/v1` 前缀。

## 题库（刷题评测）

### 数据模型

一张卷子 = `quiz_papers` 一行 + `quiz_questions` 多行。
卷子是被**对话消息触发**生成的，所以带 `message_id`（指向那条触发出题的消息）。

`status`：1=已提交（用户答案已落库），2=已评分。

### GET `/quiz-papers`

查询参数 `session_id`（必填，> 0）。返回该会话下的全部卷子（不含题目）：

```json
{
  "items": [
    { "id": 4, "session_id": 12, "message_id": 350, "target_job": "后端开发",
      "difficulty": "中等", "question_count": 5, "status": 2, "created_at": 1758000000 }
  ],
  "total": 1
}
```

前端靠 `message_id` 把卷子卡片挂到对应的对话气泡上。

### GET `/quiz-papers/{paper_id}`

返回卷子详情：在列表项基础上带 `questions` 数组。

```json
{
  "id": 4, "session_id": 12, "message_id": 350, "target_job": "后端开发",
  "difficulty": "中等", "question_count": 5, "status": 2, "created_at": 1758000000,
  "questions": [
    { "id": 21, "order_index": 0, "question": "……", "user_answer": "……",
      "score": 80, "analysis": "……" }
  ]
}
```

未评分时 `user_answer` / `score` / `analysis` 均为 `null`。

### POST `/quiz-papers/{paper_id}/submissions`

提交整卷作答，**同步评分**并返回总分、薄弱点与逐题解析。

```json
{
  "answers": [
    { "order_index": 0, "answer": "我的回答……" },
    { "order_index": 1, "answer": "……" }
  ]
}
```

```json
{
  "paper_id": 4,
  "status": 2,
  "total_score": 76,
  "weak_topics": ["索引优化"],
  "questions": [ { "id": 21, "order_index": 0, "question": "……", "user_answer": "……", "score": 80, "analysis": "……" } ]
}
```

约定：

- **一份卷子只评分一次**。已评分的卷子再提交返回 **409**（"这份题库已经评分过了"）。
  这样设计是为了让总分稳定，也避免重复计费。
- 卷子没有题目时返回 409。
- 评分先落用户答案（`status=1`）再调模型，所以模型失败也不会丢用户的作答，可以直接重试。
- `weak_topics` 会**合并进用户画像**的薄弱点。

> 已知限制（T5.9）：`weak_topics` 只写进了用户画像，**没有落 `quiz_papers`**，
> 所以刷新页面后卡片上看不到薄弱点、总分显示成平均分，要等给卷子加字段。

## 简历导出

### POST `/resumes/export`

把某条助手消息里的**「优化后的简历」那一节**（Markdown）转成 Word 并落成资源。

```json
{ "message_id": 360 }
```

```json
{
  "resource_id": 91,
  "file_name": "优化后的简历.docx",
  "content_type": "application/vnd.openxmlformats-officedocument.wordprocessingml.document",
  "download_path": "minio://interpace/user_3/resume_xxx.docx",
  "reused": false
}
```

约定：

- **只导出那一节**，不是整段回答；消息里找不到这一节时返回 **409**
  （"这条消息里没有可导出的简历内容"）。
- 生成的文件按内容哈希**去重**，同样内容再次导出时 `reused` 为 `true`、不会重复占空间。
- 前端拿到 `resource_id` 后再调 `GET /resources/{resource_id}/content` 下载。
- 消息必须是自己的，否则 404。

## 检索

### GET `/search`

检索**当前用户自己**的历史内容（笔记 / 对话 / 复盘），返回原文片段。

| 参数 | 必填 | 默认 | 约束 |
| --- | --- | --- | --- |
| `q` | 是 | — | 1~100 字符 |
| `limit` | 否 | 10 | 1~50 |
| `source_types` | 否 | 全部 | 逗号分隔：`0`对话 `1`笔记 `2`复盘 |

```json
{
  "query": "最左前缀",
  "total": 2,
  "items": [
    { "source_type": 1, "source_label": "笔记", "source_id": 5, "session_id": null,
      "title": "MySQL 索引", "content": "……命中关键词附近的原文……",
      "score": 0.8, "created_at": 1758000000 }
  ]
}
```

- 底层是 MySQL **FULLTEXT + ngram 解析器**（中文必须用 ngram，否则索引静默失效），
  不是 LIKE 模糊匹配，也不是向量检索。
- 索引在建笔记 / 消息 / 复盘时同步写入，删除时同步清理；
  历史数据用 `scripts/backfill_search_index.py` 回填。
- **刚写入的行可能搜不到**：全文索引有可见性延迟（真机验证过），
  不要用"写完立刻搜"来断言功能是否正常。

## 资源与上传

### POST `/upload/file`

`multipart/form-data`，字段名 `file`。成功返回 **201**：

```json
{
  "message": "文件上传成功",
  "resource_id": 88,
  "file_path": "minio://interpace/user_3/xxx.png",
  "file_hash": "…md5…",
  "resource_type": 1,
  "storage_scene": 0,
  "upload_purpose": 0,
  "expire_time": "2026-10-30T12:00:00",
  "is_deduplicated": false
}
```

| 字段 | 取值 |
| --- | --- |
| `resource_type` | 0文件 1图片 2音频 |
| `storage_scene` | 0长过期 1短过期 2仅提取 3永久 |
| `upload_purpose` | 0普通资源 1用户头像 |
| `is_deduplicated` | 命中相同 MD5 时复用已有资源，为 `true` |

图片等类型会在上传时顺带做解析，解析结果通过 `message` 反馈。

**错误码**：当前环境若在 `config/demo_limits.json` 里关掉了附件上传
（`cost_reduction.disable_file_upload=true`），本接口返回 **403**
（"当前环境未开放附件上传"）。前端也会隐藏「+ 附件」入口，接口这里的判断才是真正的拦截——
PDF / 图片解析出的全文会整段进上下文，一次上传能顶几十轮对话的 token。

### GET `/resources/{resource_id}/content`

返回资源**原始字节**，`Content-Type` 按资源类型设置。
只能读自己的资源：别人的、不存在的，一律 404。

### GET `/resources/content`

按 `storage_path`（如 `minio://bucket/key`）读取内容。同样只允许读自己的资源——
这个接口是给"已经有路径、但没记 resource_id"的场景（如导出的简历）用的。
