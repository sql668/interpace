# 面试记录与复盘

对应后端 `app/routes/interview_routes.py`、`app/services/interview_service.py`、
`app/services/interview_evaluation_service.py`。
通用约定见 [接口文档总览](./README.md)；语音面试的 WebSocket 协议见
[会话与对话](./会话与对话.md)。下文路径省略 `/api/v1` 前缀。

## 数据模型

一场面试 = `interviews` 表一行 + 一条"面试入口"对话消息（`message_id` 指向它）。
面试的问答明细存在 `qa_object` 这个 JSON 字段里，**不是**单独的表：

```json
[{ "question": "介绍一下你的项目", "answer": "……", "asked_at": 1758000000 }]
```

复盘是**另一张表**（`interview_evaluations`，一场面试一行，`interview_id` 唯一）：
问答记录会随着对话继续变化，而复盘是"某个时刻的结论快照"，
两者生命周期不同，所以没有塞进同一行。

## GET `/interviews/{interview_id}`

返回面试详情。归属校验：不是自己的面试一律 404。

```json
{
  "id": 7,
  "session_id": 12,
  "message_id": 345,
  "qa_object": [{ "question": "...", "answer": "..." }],
  "interview_duration": 900,
  "status": 0,
  "created_at": 1758000000,
  "updated_at": 1758000900
}
```

`status`：0=进行中，1=已结束，2=异常。

## POST `/interviews/{interview_id}/finish`

结束面试并结算时长与问答数：

```json
{
  "message": "面试已结束",
  "interview_id": 7,
  "status": 1,
  "interview_duration": 900,
  "qa_count": 6,
  "already_finished": false
}
```

**幂等**：重复调用不会报错，`already_finished` 变成 `true`、
`message` 变成"这场面试之前已经结束了"。

## POST `/interviews/{interview_id}/evaluations`

生成复盘（调大模型，同步返回，可能耗时数秒）。

```json
{
  "message": "复盘已生成",
  "evaluation": {
    "id": 3,
    "interview_id": 7,
    "summary": "整体表达清晰，但项目细节经不起追问……",
    "weak_topics": ["并发编程", "索引优化"],
    "suggestions": ["用 STAR 结构讲项目", "复习 MySQL 索引最左前缀"],
    "source": 0,
    "resource_id": null,
    "qa_count": 6,
    "created_at": 1758001000,
    "updated_at": 1758001000
  }
}
```

几点约定：

- **重新生成是覆盖式的**：面试记录可能还在增长（用户又答了几轮），
  每次生成都以最新的问答记录为准，直接覆盖旧行，不会攒出多条。
- 没有问答记录时返回 **409**（"这场面试还没有问答记录，无法复盘"）。
- 模型返回解析不了时返回 **502**，可以重试。
- 生成成功后会把 `weak_topics` **合并进用户画像**（走长期记忆的写入入口）。
  `source`：0=来自问答记录，1=来自录音。

## GET `/interviews/{interview_id}/evaluations`

读取复盘。**没生成过时返回 `200 + evaluation: null`，不是 404**：

```json
{ "message": "这场面试还没有生成复盘", "evaluation": null }
```

> 这条约定是刻意的：前端全局拦截器对 404 会弹"资源不存在"，
> 而"还没生成复盘"是正常状态，不该弹错误提示。改这个接口时别顺手改成 404。

## POST `/interviews/{interview_id}/evaluations/from-audio`

用**上传的面试录音**生成复盘（对应"面试录音从哪获取"那条需求）。

```json
{ "resource_id": 88 }
```

`resource_id` 来自先调 `POST /upload/file` 上传录音得到的返回值。

```json
{
  "message": "已根据录音生成复盘",
  "transcript": "……整段识别文本……",
  "evaluation": { "…": "结构同上" }
}
```

与"按问答记录复盘"的差别：

- 录音走**整段识别**接口（`bigmodel_nostream`），比流式快一个数量级；
- `source` 记为 1，并保存 `resource_id` 以便回溯；
- 错误码更细：录音为空 **409**、转写失败 **502**、录音里没识别到内容 **409**、
  复盘结果解析失败 **502**。

> 已知限制：上传的录音**不会挂到消息附件上**，所以删会话时不会回收这份录音，
> 靠资源 30 天过期清理兜底（记在 `docs/TODO.md` 的 T8.3）。
