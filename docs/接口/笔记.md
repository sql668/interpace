# 笔记

对应后端 `app/routes/note_routes.py`、`app/services/note_service.py`。
通用约定（鉴权、错误结构、状态码）见 [接口文档总览](./README.md)。
下文路径省略 `/api/v1` 前缀。**全部接口都按当前登录用户隔离**，
别人的笔记与不存在的笔记一律返回 404。

## 关键设计：笔记不挂在会话上

笔记有 `source_type` 与 `source_message_id` 两个字段，但**没有 `session_id`**。
这是 T2.x 的一个明确取舍（当时的 D 决策，选了"不关联 sessions"）：

- 笔记是"用户资产"，生命周期比会话长——删会话不该连带删掉用户的笔记；
- `source_message_id` 是**软引用**（不建外键），来源消息被删掉后，
  笔记仍然保留，只是在界面上不再显示"查看原对话"入口。

因此"把学习室 / 面试间的对话存成笔记"走的是下面这条**按消息导入**的接口，
而不是让笔记去挂会话。

## 字段与枚举

| 字段 | 说明 |
| --- | --- |
| `id` | 笔记 ID |
| `title` | 标题，1~255 字符，默认"未命名笔记" |
| `content` | 正文（Markdown 纯文本）。**列表接口不返回该字段**，避免列表接口拖大包 |
| `source_type` | 0=手写，1=来自对话，2=来自复盘 |
| `source_message_id` | 来源消息 ID（软引用，可能已失效） |
| `created_at` / `updated_at` | Unix 秒。列表按 `updated_at` 倒序 |

## GET `/notes`

查询参数：

| 参数 | 必填 | 默认 | 约束 |
| --- | --- | --- | --- |
| `limit` | 否 | 20 | 1~100 |
| `offset` | 否 | 0 | ≥ 0 |

```json
{
  "items": [
    {
      "id": 5,
      "title": "Redis 持久化要点",
      "source_type": 1,
      "source_message_id": 345,
      "created_at": 1758000000,
      "updated_at": 1758000100
    }
  ],
  "total": 1
}
```

注意这里用的是 `limit`/`offset`，响应里返回 `total`，
与会话接口的 `page`/`page_size`/`has_more` 不是同一套分页风格。

## POST `/notes`

成功返回 **201** 和笔记详情（含 `content`）。

```json
{
  "title": "Redis 持久化要点",
  "content": "## RDB\n……",
  "source_type": 0,
  "source_message_id": null
}
```

`title` 可省略（默认"未命名笔记"），`content` 可省略（默认空串）。

## GET `/notes/{note_id}`

返回笔记详情，比列表项多一个 `content` 字段。

## PUT `/notes/{note_id}`

**部分更新**：只改显式传入的字段，`title` 与 `content` 都可省略；
两者都不传时相当于空更新（不报错）。

```json
{ "content": "补充：AOF 的 fsync 策略" }
```

## DELETE `/notes/{note_id}`

成功返回 **204 No Content**（没有响应体）；笔记不存在或不属于当前用户时 404。
删除笔记会同时清掉它在检索索引里的条目——索引表不设外键，
不显式清理的话"删掉的笔记还能被搜到"。

## POST `/notes/import`

把**某一条对话消息**一键存成笔记，是学习室 / 面试间里"加入笔记"按钮走的接口。

```json
{ "message_id": 345, "title": "自定义标题（可省略）" }
```

响应：

```json
{
  "message": "已存入笔记",
  "created": true,
  "note": { "id": 5, "title": "介绍一下 Redis 的持久化", "content": "...", "source_type": 1, "source_message_id": 345, "created_at": 1758000000, "updated_at": 1758000000 }
}
```

- **幂等**：同一条 `message_id` 重复导入不会产生第二条笔记，
  此时 `created` 为 `false`、`note` 返回的是**已存在的那条**。
  前端据此把按钮文案在"加入笔记 / 已在笔记中"之间切换。
- 重复导入**不会覆盖**用户后来改过的内容：AI 的回答不会再变，覆盖只会让之前的编辑白费。
- 不传 `title` 时，标题取自消息里的问题文本；取不到时用"未命名笔记"。
- `source_type` 固定写 1（来自对话），`source_message_id` 写传入的消息 ID。
- 消息必须是自己的，否则 404。

## 接口实现上的两个坑（改代码时别踩回去）

1. **路由顺序**：`POST /notes/import` 必须声明在 `GET /notes/{note_id}` 之前，
   否则 `import` 会被当成 `note_id` 去解析，直接 422。
2. **导入的幂等靠"查了再写"**：`notes.source_message_id` 上没有唯一约束
   （表已存在，`create_all` 不会给已有表加约束），并发双击理论上可能写出两条。
   前端在请求期间置灰按钮，正常操作碰不到；要彻底解决得等 Alembic 加唯一索引。
