# 会话、消息与对话

对应后端 `app/routes/session_routes.py`、`app/routes/speech_routes.py`、
`app/services/stream_chat_service.py`、`app/services/speech_stream_service.py`。

通用约定（鉴权、错误结构、状态码）见 [接口文档总览](./README.md)。
下文所有路径都省略 `/api/v1` 前缀。

## 业务语义：`session_model`

会话按 `session_model` 分成三类，**同一个用户在三类里各有一批互不相干的会话**：

| 值 | 含义 | 对应的页面 |
| --- | --- | --- |
| 0 | 学习室 | StudyRoom |
| 1 | 面试间 | InterviewRoom |
| 2 | 笔记（预留给"以会话组织笔记"的形态） | 暂无独立页面 |

除了创建会话（`session_model` 写在 body 里），**其余接口都要求把 `session_model`
作为查询参数再传一次**。它同时参与两步校验：会话必须存在，且属于当前用户、
且类型匹配，任一不满足都返回 404。这样设计是为了在不加新字段的前提下，
让同一个 `session_id` 不会跨模式被误用。

## 会话

### GET `/sessions`

分页列出当前用户的会话，按创建时间倒序。

| 参数 | 位置 | 必填 | 说明 |
| --- | --- | --- | --- |
| `session_model` | query | 是 | 0/1/2 |
| `page` | query | 否 | 从 1 开始 |
| `page_size` | query | 否 | 每页条数 |

```json
{
  "page": 1,
  "page_size": 20,
  "total": 3,
  "has_more": false,
  "sessions": [
    { "id": 12, "session_model": 1, "title": "字节后端一面", "created_at": 1758000000 }
  ]
}
```

### POST `/sessions`

```json
{ "title": "字节后端一面", "session_model": 1 }
```

`session_model` 取值 0~2，默认 1；`title` 长度 1~255。

响应 **200**（不是 201，见总览里的说明）：

```json
{
  "message": "会话创建成功",
  "session": { "id": 12, "session_model": 1, "title": "字节后端一面", "created_at": 1758000000 }
}
```

### PUT `/sessions/{session_id}`

查询参数 `session_model` 必填。请求体 `{"title": "新标题"}`，响应同创建。

### DELETE `/sessions/{session_id}`

查询参数 `session_model` 必填。删除会话会**级联清理**该会话下的消息、面试记录与复盘、
题库卷与题目、检索索引、上下文摘要，并在事务提交后 best-effort 回收对象存储。

```json
{
  "message": "会话删除成功",
  "session_id": 12,
  "deleted_messages": 18,
  "deleted_interviews": 1,
  "deleted_resources": 2,
  "deleted_quizzes": 1
}
```

## 消息

### GET `/sessions/{session_id}/messages`

查询参数：`session_model`（必填）、`page`、`page_size`。

```json
{
  "session_id": 12,
  "page": 1,
  "page_size": 20,
  "has_more": true,
  "messages": [
    {
      "id": 345,
      "status": 0,
      "select_model": 1,
      "interview_id": 7,
      "request_text": "介绍一下你的项目",
      "response_text": "……",
      "request_segments": [],
      "response_segments": [],
      "created_at": 1758000000
    }
  ]
}
```

字段说明：

- `status`：0=常规对话，1=面试转写入口，2=用户已停止（详见下方"停止"）。
- `select_model`：该条消息所属模式，前端用它回显模式标签。
- `request_segments` / `response_segments`：附件段数组，元素类型为
  `{"type": "file|image|audio", "name", "url", "resource_id"}`。
- `interview_id`：面试场景下指向 `interviews` 表，前端据此渲染面试卡片。

## 流式对话（SSE）

### POST `/sessions/{session_id}/stream-chat`

查询参数：`session_model`（必填）、`agent_name`、`scene`（后两个用于指定智能体与场景，
不传走默认路由）。

请求体：

```json
{
  "request_text": "介绍一下 Redis 的持久化",
  "select_model": 0,
  "provider": "deepseek",
  "segments": [
    { "type": "image", "name": "架构图.png", "resource_id": 88 }
  ]
}
```

响应是 `text/event-stream`，每帧格式固定为 `data: {json}\n\n`（没有 `event:` 字段，
前端按 `type` 分发）。事件序列：

| `type` | 载荷 | 说明 |
| --- | --- | --- |
| `start` | `{"message_id": 345}` | 消息行已落库。**前端要拿这个 id 调停止接口**，并在此时把消息气泡挂到界面上 |
| `delta` | `{"text": "增量"}` | 正文增量，可能很多帧 |
| `error` | `{"message": "..."}` | 出错；正文已生成的部分仍会落库 |
| `done` | 见下 | 一定出现，且是最后一帧 |

`done` 的完整载荷：

```json
{
  "type": "done",
  "response_text": "完整正文",
  "stopped": false,
  "quiz_paper_id": null,
  "profile_proposal_id": null,
  "interview_id": 7
}
```

- `stopped`：`true` 表示本轮被用户主动停止；
- `quiz_paper_id` / `profile_proposal_id` / `interview_id`：本轮触发了出题 / 画像提案 /
  面试记录时才有值，前端据此渲染对应卡片。

### POST `/sessions/{session_id}/stream-chat/stop`

查询参数只有 `session_id`（**不带 `session_model`**）。请求体：

```json
{ "message_id": 345 }
```

`message_id` 取自 `start` 事件。响应：

```json
{ "message": "已请求停止生成", "message_id": 345, "first_request": true }
```

- 停止是**幂等**的：重复调用不会报错，`first_request` 变成 `false`、
  `message` 变成"该消息此前已请求停止"。
- 后端在生成循环里轮询取消标志，命中后立刻跳出、`close()` 掉模型流连接，
  并把已生成内容与"已停止"状态落库（`status=2`）。
- 停止接口与前端 `AbortController` 是**双保险**：即使停止接口调用失败，
  前端也会断开本地渲染。

## 语音面试（WebSocket）

### WS `/api/v1/sessions/{session_id}/speech/stream`

查询参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `session_model` | 是 | 面试场景传 1 |
| `token` | 是 | `access_token`，**不能放在请求头**——浏览器 WebSocket API 不支持自定义头 |

鉴权在 `accept()` **之前**完成：token 无效直接关闭连接，不会给未授权连接开门。

链路是 **火山 ASR → 面试 Agent（LangGraph）→ 火山 TTS**，全部流式，
API Key 只留在后端，不下发浏览器。

前端 → 后端：

| 帧 | 载荷 | 说明 |
| --- | --- | --- |
| 文本 | `{"type": "start_utterance"}` | 开始这一句，会新建一趟 ASR 会话 |
| 二进制 | — | 16kHz / 16bit / 单声道 PCM 分片 |
| 文本 | `{"type": "end_utterance"}` | 说完了（也可以不发，服务端 VAD 会分句） |
| 文本 | `{"type": "text", "text": "..."}` | 直接给文字，跳过 ASR（调试与降级用） |

后端 → 前端：

| `type` | 载荷 | 说明 |
| --- | --- | --- |
| `ready` | `{"asr_sample_rate", "tts_sample_rate", "tts_format"}` | 连接就绪，前端按这个规格重采样 |
| `asr_partial` | `{"text": "..."}` | 识别中间结果，用于实时上字幕 |
| `asr_final` | `{"text": "..."}` | 本句最终识别结果 |
| `reply` | `{"text", "interview_id", "message_id"}` | 面试官的话（文字部分） |
| `tts_start` | `{"format", "sample_rate"}` | 随后的二进制帧是面试官语音 |
| `tts_subtitle` | `{"text", "start_ms", "end_ms", "phonemes"}` | 字幕（当前音色拿不到字级时间戳，字段可能为空数组） |
| `tts_end` | — | 本轮音频推完，前端可以开始说下一句 |
| `error` | `{"message": "..."}` | 业务错误 |

音频参数：ASR 输入 16kHz，TTS 输出 24kHz / `pcm`。

**为什么按"一句话一趟 ASR 会话"**：火山要求音频流持续有包，8 秒收不到就断会话。
面试天然一问一答，按句开会话既避开超时，又不用自己写静音检测。

## 面试记录与复盘

面试场景的这几条接口写在 `app/routes/interview_routes.py`，
复盘相关见 [接口文档总览](./README.md) 索引里的 `interviews/*`。
其中一条**反直觉的约定**再强调一次：

> `GET /interviews/{id}/evaluations` 在没生成过复盘时返回 **200 + `evaluation: null`**，
> 不是 404。前端全局拦截器对 404 会弹"资源不存在"，所以这里刻意不用 404。
