# 数据库变更流程

> 对应 `docs/TODO.md` 的 T10.7（决策 D24：补基线迁移、正式启用 Alembic）。

## 一句话规则

**表结构的唯一权威是 `alembic/versions/` 下的迁移文件。** 改了 `app/db/models.py` 就要配一条迁移，不能只改模型。

## 为什么现在才补

在这之前，schema 完全来自 `app/main.py` lifespan 里的 `Base.metadata.create_all(engine)`——那是「建缺失的表」，**既不会加列、也不会改类型、更不会加索引**。等于 schema 变更没有任何版本管理：

- 加列 / 改类型没有任何可回滚的路径；
- 也无法确认各环境 schema 是否一致。

这不是理论风险，实测就撞上了：开发库里 `chat_messages.status` 的列注释还停留在旧版（「0常规聊天，1面试转写入口」），而模型里早就加了几个新取值——因为 `create_all` **永远不会修改已存在的表**。全新用迁移建的库注释才是对的。

## 现状

- `598c8ac58d95_baseline_schema.py` 是**基线迁移**：用显式 DDL 固化「`create_all` 会建出来的全部表」。它不描述某一次变更，而是给项目一个起点。
- 原来的 `8d4d0586ab85_init_user_table.py`（`upgrade()` 是空的 `pass`）**已删除**。
- 已经跑过 `create_all` 的开发库**不要执行基线迁移**（表已经在了），用 `alembic stamp` 标记即可。

## 日常流程

### 1. 改模型

改 `app/db/models.py`。

### 2. 生成迁移

```bash
cd interpace-backend
uv run alembic revision --autogenerate -m "加 xxx 字段"
```

**必须人工检查生成的文件**。autogenerate 有几个已知盲区：

- 索引的 `mysql_prefix='FULLTEXT'` / `mysql_with_parser='ngram'` 能识别，但改索引时容易漏；
- 列注释的变更不会生成语句（本项目的注释变更很多，重要的话手动补）；
- 删表 / 删列会被生成成 `op.drop_*`，删数据前先确认。

### 3. 在开发库执行

```bash
uv run alembic upgrade head
```

### 4. 新环境（或生产）首次部署

```bash
uv run alembic upgrade head        # 从零建到最新
```

**生产环境不会自动建表**：`main.py` 只在非生产环境跑 `create_all`（图开发方便），生产必须显式执行迁移。这样「迁移忘了跑」会立刻暴露，而不是被 `create_all` 掩盖成「表面能用、schema 是旧的」。

### 5. 已有数据的库首次接入 Alembic

如果某个库的 schema 已经和当前模型一致（例如一直在用 `create_all`），**不要**执行基线迁移，直接标记：

```bash
uv run alembic stamp head
```

### 6. 回滚

```bash
uv run alembic downgrade -1         # 回退一版
uv run alembic history              # 看历史
uv run alembic current              # 看当前版本
```

基线迁移的 `downgrade()` 会删掉所有表——**只在空库上用它**，别在生产环境执行。

## 校验迁移是否与模型一致

生成的迁移是靠人检查的，所以给一条自检命令（对着一个空库跑迁移，再和 `create_all` 的结构比对）：

```bash
# 1) 建一个空的验证库（排序规则要和目标库一致，否则列排序规则会有差异）
# 2) 在验证库上跑迁移
MYSQL_URL="mysql+pymysql://用户:密码@主机:3306/验证库" uv run alembic upgrade head
# 3) 比对 information_schema 的 COLUMNS / STATISTICS / KEY_COLUMN_USAGE
```

比对时**只看列、索引、外键三个维度，并忽略自动生成的外键约束名**（`xxx_ibfk_1/2/3` 的编号顺序由建表顺序决定，不是语义差异）。

核对基线时的结论：17 张表、51 个索引、24 个外键，与 `create_all` **零差异**。
